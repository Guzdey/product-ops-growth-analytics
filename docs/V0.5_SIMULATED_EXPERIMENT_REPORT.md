# v0.5.0 模拟渠道与 A/B 实验报告

> **来源声明：本文所有渠道、成本、金额、实验分组和结果均为模拟数据 / SIMULATED。**
> 它们用于演示增长运营分析方法，不是 Retailrocket 的真实字段或真实业务成果。

## 1. 业务问题

增长运营需要判断一个新方案是否值得上线，同时回答两个问题：

1. 实验组的用户转化率是否比对照组更高？
2. 即使统计显著，效应大小、样本量和退款率护栏是否允许逐步放量？

项目提供两个预登记场景，避免只展示“成功实验”：

| 场景 | 对照组 | 实验组 | 设计目的 |
|---|---:|---:|---|
| 无效果 | 10,000 人 | 10,000 人 | 验证分析能正确得出“不上线” |
| 正向效果 | 10,000 人 | 10,000 人 | 验证效应、区间、显著性和护栏的联合判断 |

固定随机种子为 `20260809`。模拟参与者使用 `sim_20260809_...` 字符串 ID，既不复用也不
伪装成真实 `visitorid`。

## 2. 数据与技术边界

```text
Python 固定种子生成 → synthetic 输入表 → SQL 聚合指标
→ Python 双样本比例检验 → 聚合导出 → 独立 Streamlit 页面
```

- 本地明细：`synthetic.experiment_assignment`、`synthetic.channel_daily_input`；
- SQL 指标：`synthetic.experiment_arm_metrics`、`channel_daily_metrics`、
  `channel_summary`、`guardrail_summary`；
- Python 统计结果：`synthetic.experiment_results`；
- 公开仓库只保留六张聚合快照，不导出参与者 ID 或模拟订单 ID；
- 所有表和文件均带 `data_origin='synthetic'`，并声明不包含真实 Retailrocket 数据。

## 3. 指标口径

| 指标 | 公式 | 用途 |
|---|---|---|
| 实验主指标 | `converted_users / assigned_users` | 按意向处理原则评价整体方案 |
| CTR | `clicks / impressions` | 判断素材或入口吸引力 |
| 点击后 CVR | `conversions / clicks` | 判断落地页或购买承接效率 |
| CAC | `spend / conversions` | 衡量单次模拟获客成本 |
| ROAS | `simulated_gmv / spend` | 衡量模拟投放回报 |
| 模拟 AOV | `simulated_gmv / simulated_orders` | 衡量模拟订单金额水平 |
| 退款率护栏 | `refunded_users / converted_users` | 防止转化提升以质量下降为代价 |

主指标采用双侧双样本比例 z 检验，显著性水平 `α=0.05`；同时报告绝对提升、相对提升、
95% 置信区间和 p 值。每组最低样本门槛为 10,000，退款率允许的最大相对恶化为 1 个
百分点。

## 4. 实验结果

| 场景 | 对照转化率 | 实验转化率 | 绝对提升 | 相对提升 | 95% CI | p 值 | 决策 |
|---|---:|---:|---:|---:|---:|---:|---|
| 无效果 | 8.0% | 8.0% | 0.0pp | 0.0% | [-0.752pp, +0.752pp] | 1.0000 | 不上线 |
| 正向效果 | 8.0% | 9.2% | +1.2pp | +15.0% | [+0.423pp, +1.977pp] | 0.0025 | 逐步放量候选 |

无效果场景的区间包含 0，不能把“样本跑完”误解成“方案有效”。正向场景的效应为正、
置信区间不含 0、样本达到门槛且退款率护栏通过，因此只进入逐步放量候选，而不是直接
宣称全面上线成功。

## 5. 运营动作

- 无效果：停止放量，检查用户洞察、方案差异强度和埋点完整性，再决定是否重做实验；
- 正向效果：按 10%→30%→50% 分阶段放量，持续监控转化率和退款率；
- 任一场景：检查样本比例失衡（SRM）、跨组污染、重复曝光和指标口径漂移；
- 若护栏恶化超过 1 个百分点，即使主指标显著也停止放量并定位原因。

## 6. 复现与验证

```powershell
python -m product_ops.cli experiment --config config\project.example.toml --json
python tools/build_experiment_snapshot.py
python -m pytest tests/test_experiments.py tests/test_dashboard.py tests/test_streamlit_app.py
```

固定种子重复生成的明细指纹一致；专项测试覆盖场景效应、置信区间、p 值、来源隔离、
模拟 ID 前缀、转化必须发生于点击后、订单金额契约和聚合导出禁止明细字段。

## 7. 限制

- 生成机制是人为设定，不能推断真实渠道效果或真实用户偏好；
- 模拟 GMV、AOV、CAC 和 ROAS 只用于演示公式与决策流程；
- 当前使用简单比例检验，未处理网络效应、多重检验、序贯检验或长期效应；
- 真正上线前还需做实验分流、功效分析、埋点验收和业务风险评审。

## 幂等性与性能

- 首次成功的 13 步全量分层构建用时约 38.0 秒；每个建表语句独立提交并记录状态。
- 相同输入和 SQL 的第二次构建用时 0.339 秒，13 个模型步骤全部复用，核心表行数不变。
- 代表性的 275.6 万事件与 78.8 万商品分类历史 ASOF 关联，`EXPLAIN ANALYZE`
  显示总用时约 0.105 秒；该结果是本机热缓存下的单次测量，不作为跨机器性能承诺。
- DuckDB 文件为 2,604,937,216 bytes（约 2.60 GB）；验证后 D 盘仍有约 740 GiB 可用空间。

## 已知局限

- Retailrocket 不含注册时间、真实价格、订单金额、渠道、成本或实验分组；本阶段不计算
  GMV、AOV、CAC、ROAS 或 LTV。
- 除 `categoryid`、`available` 外，商品属性保持匿名，不能解释为品牌、价格或商品名称。
- `transactionid` 是订单代理键；商品交易事件行数不能冒充订单数。
- 本阶段只完成可信数据底座，漏斗、留存、复购、生命周期和品类机会将在 `v0.3.0`
  通过版本化 SQL 正式计算。

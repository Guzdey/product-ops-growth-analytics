## 新增能力

- 六页 Streamlit/Plotly 看板：管理摘要、流量活跃、漏斗路径、留存生命周期、商品品类和
  数据质量；
- 日期、首会话分群、Cohort 周、根品类、样本门槛和机会候选筛选；
- 三条真实运营故事，均按 `What / So What / Now What / How to Verify` 组织；
- 17 张约 427 KiB 的真实数据聚合快照，可在没有全量 CSV 或 DuckDB 时运行公开演示；
- 数据来源、分母、时间窗、真实/模拟边界、空状态和深色主题支持；
- 看板来源契约、快照清单与 Hash、交互和六页启动测试。

## 三条运营结论

1. **优先诊断浏览到加购。** 该步骤贡献严格两步漏斗总流失的 98.52%，但数据不足以直接
   判断具体页面原因；应先拆分品类、会话深度和时点可售状态，再实验验证。
2. **加购未购召回只做小规模测试。** 其 D7 留存比仅浏览高 0.656pp，未达到预登记的
   5pp 业务门槛，不能把统计显著写成召回收益。
3. **匿名品类 299 进入人工诊断清单。** 其会话转化率比同父级合格品类中位数低
   2.119pp；分类缺少业务语义，因此不能直接套用具体营销方案。

## 数据与隐私

- 指标来自 Retailrocket 官方完整数据的 `v0.3.0` SQL 聚合结果，`data_origin='real'`；
- 看板不直接扫描原始 CSV，也不使用桌面教学样例得出结论；
- 公开快照不含 `visitorid`、`transactionid`、`session_id` 或原始行为明细；
- 高基数行为路径和商品排行经过展示性截取，不能用快照重新推导总体指标；
- 数据没有金额、渠道、成本或实验分组，不展示真实 GMV、AOV、CAC、ROAS 或 LTV。
